# ขายสินค้าต่อได้เมื่ออินเทอร์เน็ตหรือเว็บเซิร์ฟเวอร์ล่ม — แนวทางและคำแนะนำ

ระบบบริหารบัญชี ร้านค้าสหการ · ปรับปรุง 3 พ.ย. 2569

## ปัญหา

หน้า POS บนเว็บทำงานแบบออนไลน์ทุกขั้นตอน: ค้นหาสินค้า ตรวจสต๊อก และบันทึกการขาย (`POST /api/sales`)
ต้องคุยกับเซิร์ฟเวอร์ทุกครั้ง ถ้าอินเทอร์เน็ตของร้านล่ม หรือเซิร์ฟเวอร์ (coac.rvc.ac.th) ล่ม
พนักงานจะขายผ่านระบบไม่ได้เลย ต้องจดลงกระดาษแล้วมาคีย์ย้อนหลัง ซึ่งช้าและผิดพลาดง่าย

สิ่งที่ต้องการคือ **ขายต่อได้ระยะหนึ่ง แล้วส่งยอดเข้าระบบเองเมื่อเชื่อมต่อได้อีกครั้ง โดยไม่บันทึกซ้ำและไม่สูญหาย**

## หลักการที่ใช้ได้ทุกวิธี (offline-first)

1. **เก็บข้อมูลสินค้าไว้ในเครื่อง** — ชื่อ ราคา บาร์โค้ด บาร์โค้ดแพ็ค ราคายกแพ็ค รูปภาพ สต๊อก โหลดทั้งหมดครั้งแรก แล้วดึงเฉพาะที่เปลี่ยน
2. **บันทึกการขายลงเครื่องก่อนเสมอ** (คิวรอส่ง) แล้วค่อยส่งขึ้นเซิร์ฟเวอร์ ไม่ใช่ส่งตรง
3. **ทุกรายการขายมีรหัสที่เครื่องสร้างเอง (UUID)** — ส่งซ้ำกี่ครั้งเซิร์ฟเวอร์ก็บันทึกครั้งเดียว (idempotent)
   แก้ปัญหา "กดชำระแล้วเน็ตหลุด ไม่รู้ว่าบันทึกหรือยัง"
4. **บันทึกเวลาขายจริง** ไม่ใช่เวลาที่ส่งถึงเซิร์ฟเวอร์ เพื่อให้ยอดลงวันบัญชีที่ถูกต้อง
5. **ยอมรับการขายที่เกิดขึ้นแล้ว** — ขายตอนออฟไลน์ ลูกค้าจ่ายเงินแล้ว จะปฏิเสธไม่ได้
   เซิร์ฟเวอร์บันทึกตามที่ขายจริงแม้สต๊อกติดลบหรือราคาเปลี่ยนไปแล้ว แต่ **ติดหมายเหตุเตือน** ให้ตรวจสอบ
6. **รายการที่บันทึกไม่ได้จริง ๆ ไม่ทิ้ง** — เก็บไว้ให้ผู้ดูแลระบบตรวจและจัดการ

## ทางเลือกที่พิจารณา

| วิธี | ทำงานเมื่อ | ข้อดี | ข้อจำกัด |
|---|---|---|---|
| **A. แอป Android แบบ Native (offline-first)** ✅ แนะนำ | ทั้งเน็ตล่มและเซิร์ฟเวอร์ล่ม | ฐานข้อมูลในเครื่อง (Room) เชื่อถือได้ ส่งยอดเบื้องหลังด้วย WorkManager แม้ปิดแอป ใช้กล้องสแกนบาร์โค้ด/เครื่องสแกน USB/Bluetooth ได้ เก็บโทเคนอย่างปลอดภัย | ต้องพัฒนาและดูแลแอปแยก |
| B. ทำหน้า POS บนเว็บให้เป็น PWA (Service Worker + IndexedDB) | ทั้งสองกรณี (ถ้าเคยเปิดหน้าไว้แล้ว) | ใช้โค้ดเว็บเดิมได้มาก ไม่ต้องติดตั้งแอป | เบราว์เซอร์ล้างข้อมูลได้เอง (iOS/โหมดประหยัดพื้นที่) ส่งยอดเบื้องหลังไม่แน่นอน ปิดแท็บแล้วคิวค้าง ต้องใช้ HTTPS เสมอ ระบบ session/CSRF เดิมไม่เหมาะกับการส่งย้อนหลัง |
| C. เซิร์ฟเวอร์สำรองในร้าน (mini PC/Raspberry Pi รันระบบเดียวกัน แล้วซิงก์ฐานข้อมูล) | เน็ตล่ม (เซิร์ฟเวอร์ในร้านยังทำงาน) | หน้าเว็บเดิมใช้ได้ทั้งหมด | ซิงก์ฐานข้อมูลสองทางซับซ้อนมาก (เลขที่เอกสารชนกัน สต๊อก บัญชีผู้ฝาก) ต้องมีคนดูแลเครื่อง ไฟดับก็ล่มเหมือนกัน |
| D. 4G/5G สำรอง (pocket WiFi / ซิมในแท็บเล็ต) | เน็ตร้านล่มเท่านั้น | ถูกและเร็ว ทำได้ทันที | ไม่ช่วยเมื่อเซิร์ฟเวอร์ล่ม |
| E. จดกระดาษ + นำเข้ายอดขายภายหลัง (หน้า "นำเข้ายอดขายจาก POS" ที่มีอยู่) | ทุกกรณี | ไม่ต้องลงทุน | ช้า ผิดพลาดง่าย ไม่มีสต๊อกให้ดูระหว่างขาย |

## คำแนะนำ

1. **ระยะยาว: ใช้แอป Android แบบ Native (วิธี A)** เป็นเครื่องขายหลักหน้าร้าน
   ฝั่งเซิร์ฟเวอร์ทำเสร็จแล้วในรอบนี้ (ดูหัวข้อถัดไป) และมีสเปกสำหรับสร้างแอปใน
   [`docs/android-pos-app.md`](android-pos-app.md) พร้อมส่งให้ Claude Code อีกเซสชันพัฒนาต่อ
2. **ทำทันที (ต้นทุนต่ำ): มีอินเทอร์เน็ตสำรอง 4G (วิธี D)** — แก้กรณีเน็ตร้านล่มซึ่งเกิดบ่อยกว่าเซิร์ฟเวอร์ล่ม
3. **คงหน้า POS บนเว็บไว้** สำหรับคอมพิวเตอร์ และใช้เป็นทางสำรองเมื่อแอปมีปัญหา
4. **แผนฉุกเฉินบนกระดาษ (วิธี E)** ยังควรมีไว้ เช่น แท็บเล็ตแบตหมด
5. ไม่แนะนำวิธี C (เซิร์ฟเวอร์ในร้าน) เพราะการซิงก์ฐานข้อมูลบัญชีสองทางเสี่ยงต่อความถูกต้องของยอดเงินผู้ฝากขาย

### ขอบเขตที่ควรกำหนด ("ขายต่อได้ระยะหนึ่ง")

- แอปขายออฟไลน์ได้ไม่จำกัดเวลา แต่ **แสดงคำเตือนเมื่อข้อมูลสินค้าเก่ากว่า 24 ชั่วโมง** และ
  **เมื่อมีรายการค้างส่งนานเกิน 1 วัน** (ผู้ดูแลเห็นจำนวนค้างส่งของแต่ละเครื่องในหน้า "อุปกรณ์ POS")
- สต๊อกในเครื่องหักตามที่ขายเอง แต่เครื่องอื่นไม่รู้ จึงอาจขายเกินสต๊อกจริงได้ → เซิร์ฟเวอร์ยอมรับ
  พร้อมเตือน "สต๊อกติดลบ ควรตรวจนับ"
- การนับเงินในลิ้นชัก สรุปบัญชีรายวัน และการแก้ไขการขาย ต้องทำตอนออนไลน์ ถ้าวันนั้นสรุปบัญชีไปแล้ว
  แล้วยอดออฟไลน์เพิ่งส่งเข้ามา ระบบปรับยอดลิ้นชักให้และติดหมายเหตุให้ตรวจสรุปบัญชีวันนั้นอีกครั้ง

## สิ่งที่ทำแล้วฝั่งเซิร์ฟเวอร์ (รอบนี้)

- ตาราง `pos_devices` และ `pos_device_sales` (**ต้องรัน migration 0061** ที่หน้าจัดการฐานข้อมูล)
- จับคู่อุปกรณ์ด้วยรหัส 6 ตัวแบบ Google TV: แอปแสดงรหัส → ผู้ดูแลระบบ/ผู้จัดการกรอกที่เมนู
  **รายงานและระบบ › อุปกรณ์ POS (Android)** แล้วเลือกบัญชีที่เครื่องใช้ขาย → แอปได้โทเคนของเครื่อง
- API `/api/device/v1/*`: ข้อมูลเครื่อง/การตั้งค่า, รายการสินค้าแบบโหลดทั้งหมดและเฉพาะที่เปลี่ยน, รูปสินค้า,
  ส่งยอดขายเป็นชุด (ไม่บันทึกซ้ำ), ลิ้นชักเงิน, ประวัติการขายของฉัน, ขอแก้ไขการขาย
- หน้าเว็บจัดการอุปกรณ์: เปลี่ยนชื่อ/บัญชีผู้ขาย ยกเลิกการจับคู่ ดูสถานะออนไลน์ จำนวนรายการค้างในเครื่อง
  และรายการขายที่บันทึกไม่สำเร็จ (บันทึกอีกครั้ง / ระบุว่าจัดการแล้ว)

รายละเอียด API อยู่ใน [`docs/android-pos-app.md`](android-pos-app.md)
